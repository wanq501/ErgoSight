# ErgoSight

**Physically grounded evaluation of how multimodal large language models perceive the visual ergonomics of user interfaces**

This repository accompanies the article *ErgoSight: Physically Grounded Evaluation of How Multimodal Large Language Models Perceive the Visual Ergonomics of User Interfaces*, submitted to *Displays*.

Visual ergonomics depends on physical quantities that a screenshot does not contain, such as the visual angle of text or its contrast under daylight. ErgoSight derives every label from measured quantities under a specified display condition (the Physical Measurement Oracle, PMO) and renders those quantities as views that make them visible (the Physical View Lens, PVL). ErgoSight-Bench poses 4,275 questions over eight criteria, six display conditions and four task levels.

## Contents of this release

| Path | Content |
| --- | --- |
| `data/questions.jsonl` | the 4,275 questions of ErgoSight-Bench with criterion, task level, display condition, options, label, measured value, subsets, position-swapped twin, and the exact user prompt in S0, S1 and S2 |
| `data/answers.csv.gz` | all 66,261 replies of the eight evaluated MLLMs with tokens, latency and cost per request |
| `data/criteria.csv`, `data/displays.csv`, `data/settings.csv`, `data/models.csv` | the eight criteria with their thresholds, the six display conditions, the input settings, and the evaluated models |
| `data/samples/` | representative interfaces rendered under the display conditions, with their measured violations |
| `prompts/` | the four prompts of ErgoSight: generation, polish, repair and question prompt |
| `ergosight/` | the evaluation toolkit: loading, reply reading and the metrics of the paper |
| `scripts/reproduce_tables.py` | regenerates the main results of the paper from the released files |
| `scripts/reproduce_revision.py` | regenerates the additional analyses of the revised paper: errors fixed by the measured values, page-level bootstrap, Holm-corrected pairwise tests, real against generated pages on the core subset, answer changes with and without a view, gains per type of view, sensitivity of the visual angle labels to the cap-height ratio, misses and false alarms, and the output length of Qwen3.5-397B-A17B |
| `results/` | the output of both scripts |

ErgoSight-Bench comprises 1,659 interfaces, 1,470 generated by three LLMs and 189 real web pages, and its questions are posed on 1,638 of them. The rendered screenshots and PVL views of every question are distributed as the release asset `ErgoSight-Bench-images.zip`, which unpacks into `data/images/`.

**Release plan.** This release contains everything needed to verify the results of the paper. The interface generation pipeline with its polish and repair loop, the measurement engine of the PMO and the renderer of the PVL views will be released upon publication.

## Quick start

```bash
pip install -r requirements.txt
python scripts/reproduce_tables.py
python scripts/reproduce_revision.py
```

Both scripts read only the files in `data/`, write one CSV per result to `results/` and print them. Each runs in about a minute on a laptop.

```python
from ergosight import load_questions, load_answers, accuracy
q = load_questions()
a = load_answers(questions=q)
core = a[(a.setting == 'S0') & a.qid.isin(q[q.core_subset].qid)]
print(core.groupby('model').correct.mean() * 100)
```

## Main results

Accuracy in S0 on the 891 questions of the core subset, where every model answers every question, against a chance level of 41.6%, and in the oracle setting S2, where the measured value is given. Given the measured values, the four models evaluated in S2 fix 85.0% of their S0 errors, a net reduction of 79.6%.

## Data format

Each line of `questions.jsonl` is one question.

| Field | Meaning |
| --- | --- |
| `qid` | question id |
| `source_type` | `generated` or `real` |
| `criterion` | TC text contrast, NC boundary contrast, VA visual angle, TS target size, RF reflow, TI text integrity, CV color vision, AC ambient contrast |
| `level` | L1 detect, L2 locate, L3 compare, L4 estimate |
| `display`, `display_name` | D1 desktop, D2 tablet, D3 phone, D4 reflow, D5 deuteranopia, D6 daylight |
| `page_id`, `domain`, `generator`, `construction` | the interface, its HMI domain, the generating LLM, and how the page was built (`direct`, `defect`, `pair`, `repaired`, `real`) |
| `question`, `options`, `answer` | the question, its options and the letter of the correct option |
| `measured`, `measured_value` | the measurement of the PMO behind the label |
| `core_subset`, `extended_subset` | membership of the 891-question core subset and the 1,781-question extended subset |
| `twin_of` | the position-swapped twin of an L3 question |
| `inputs` | the images given in each setting |
| `prompts` | the exact user prompt in S0, S1 and S2 |

`answers.csv.gz` has one row per request with the columns `model`, `setting`, `qid`, `reply`, `tokens_in`, `tokens_out`, `latency_s`, `cost_usd` and `finish_reason`. The evaluated models answer the core subset (Claude Sonnet 5.5), the extended subset (Gemini 3.8 Flash, GPT-5.4 mini, Qwen3.5-397B-A17B) or the full benchmark (the other four), as listed in `data/models.csv`.
